# D7 web accessibility audit (DSN-050)

Scope: the web app (gallery entries and the e2e stack pages). Mobile is a later PR.
Specs live in `packages/web/e2e/a11y/**`; Playwright projects `a11y` (gallery, `PW_VISUAL=1`) and `a11y-stack` (real pages, `TEST_ENV=e2e`).

## Method

- axe (`@axe-core/playwright`), tags wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa, best-practice. The wcag22aa tag switches on target-size (24px), which the earlier default run did not check. Serious and critical findings fail the tests.
- Contrast is measured on rendered pixels, not computed from tokens. Each text element is screenshotted as drawn and again with all text transparent. The glyph pixels are those that differ between the two shots and lie on the line between the background and the text colour. The WCAG ratio is taken at the worst glyph pixel. Threshold: 4.5 for normal text, 3 for large (24px, or 18.66px bold). Excluded: disabled controls (WCAG exempt), closed `details` content, screen-reader-only boxes.
- The R2.6 worst points are rebuilt as stacks of the real `--pb-glass-*` tokens (`e2e/a11y/support/worstPoints.ts`) and measured the same way, in both themes.
- Keyboard: Tab from the top, every enabled control reached in DOM order, no positive tabindex, a visible focus indicator at each stop (outline, ring, border or background change). Dialogs: Tab (n+1) times then Shift+Tab (n+1) times, n being the tab stops in the dialog, stay inside, Esc closes and focus returns to the opener.

## Whole-gallery sweep

All 127 gallery entries x 2 themes, 4,972 text elements measured, all at or above AA. Entries that open a modal, drawer or sheet (rendered through a portal onto the scrim) are measured inside the `[role="dialog"]` panel; the page behind the scrim is inert and not measured. The account menu is a non-modal dialog, so its entry is measured as a whole shell. Input and textarea values and placeholders, native select chosen-option text and date input text are measured too: lowest 6.20:1 dark ("Search planned items" placeholder), 5.41:1 light (manual transaction amount placeholder).

Lowest normal text: 5.18:1 dark (Overview/Current "zł a day"), 4.68:1 light (TransactionDialogs/MapSheetOver "Over budget"). Lowest large text: 7.05:1 dark, 6.14:1 light. Ratios are compared unrounded against 4.5 and 3.

## Fixes (web presentation code, behaviour preserving)

1. `Input.tsx`: password Show/Hide button gets a 44x32 minimum hit area (target-size). Text position unchanged.
2. `CategoriesView.tsx`: archived category rows use opacity 0.85 instead of 0.7; light-theme dim text was 3.5-3.9:1, now at least 4.88:1.
3. `glass/atoms/Avatar.tsx`: the initials sit on the tint over a solid page-base underlay instead of a translucent fill; initials were 4.3-4.4:1 over a neighbouring avatar's ring or plain glass.

The 509 visual baselines stay valid: `pnpm test:visual:update` in Docker produced no changed snapshot and `pnpm test:visual` is green (the changes are below the screenshot tolerance).

## Keyboard pass

- Gallery: every entry x theme, tab order equals DOM order, no positive tabindex, visible focus on every stop; skip link focus on Shell/Overview; trap tests on all modal, drawer, sheet, account menu, clone plan and transaction dialog entries.
- Real app: /dashboard, /transactions, /plans, /categories, /settings/profile walked the same way; the Clone plan dialog on /plans traps Tab, closes on Esc and returns focus to the Clone button.
