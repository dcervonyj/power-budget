# ADR-003: Always-on hosting on Render Starter in Frankfurt

- **Status**: Accepted (owner sign-off 23 Oct 2026)
- **Date**: 2026-10-23
- **Supersedes**: the runtime choice of ADR-002 (Render free, Oregon, Upstash)
- **Relates to**: HOST-001, HOST-002, INF-009, INF-010

## Context

Bank sync (Enable Banking, Wise webhooks) and the BullMQ crons need an API that is always
on; the Render free plan sleeps after 15 minutes. The v1.1 plan (BACKLOG §7) assumed an
EU VPS (Hetzner CX23, about €6/month) for that.

Facts checked on 23 Oct 2026:

- Hetzner CX and CAX plans have been unavailable since about 2 Sep 2026; CX23 only
  reappears for minutes at a time. Plans that can be ordered start at CPX12 (2 GB),
  €11.99/month before VAT.
- The existing Render service runs in Oregon while Neon is in Frankfurt (AWS
  eu-central-1), so every query crossed the Atlantic.
- The Upstash free database had been deleted for inactivity, which broke every deploy
  since 21 Oct (`getaddrinfo ENOTFOUND`).
- The embedded worker listens on 5 queues. Idle BullMQ polling alone is a few million
  Redis commands a month, far over the Upstash free quota of 500k.

## Decision

| Concern        | Choice                                | Cost/month |
| -------------- | ------------------------------------- | ---------- |
| API + worker   | Render Starter web service, Frankfurt | $7         |
| Worker process | Still embedded (`START_WORKER=true`)  | —          |
| Redis          | Render Key Value free, Frankfurt      | $0         |
| Postgres       | Neon free, Frankfurt (unchanged)      | $0         |
| Web            | Cloudflare Pages (unchanged)          | $0         |
| Email          | Resend free (unchanged)               | $0         |

`render.yaml` describes both services. The new web service is named `power-budget-api-eu`
because Render cannot move a service between regions; the Oregon service is deleted once
the Frankfurt one is healthy. `REDIS_URL` comes from the Key Value instance through
`fromService`, `JWT_SECRET` is generated by Render, and `KEK_BASE64` must be copied from
the old service because it decrypts secrets already stored in Neon.

## Rejected alternatives

| Option                     | Why not                                                  |
| -------------------------- | -------------------------------------------------------- |
| Hetzner CX23 (€5.99 + VAT) | Not purchasable; a restock cannot be planned around      |
| Hetzner CPX12/CPX22        | €12–20 + VAT plus server upkeep, for no gain over Render |
| Upstash free               | Idle BullMQ polling exhausts 500k commands in a few days |
| Upstash pay as you go      | About $8–10/month at the current polling rate            |
| Render Key Value Starter   | $10/month; persistence is not needed yet (see below)     |
| Keep the Oregon service    | ~150 ms per Neon round trip                              |

## Consequences

- Total runtime cost is $7/month; no server to patch.
- Key Value free has no disk: a restart drops queued jobs. Notifications survive because
  the outbox lives in Postgres (the 5-minute `outbox-relay` cron enqueues them again), and
  the crons are in-process `@Cron` jobs, not BullMQ repeatables, so nothing to re-register. Move to
  Key Value Starter once bank sync carries real data.
- HOST-002 shrinks to setting the dashboard secrets and checking `/health`; Docker
  Compose, Caddy and the SSH deploy job are not needed. A separate worker service stays
  optional (a Render background worker is another $7).
- HOST-003 (domain) is unchanged: Wise webhooks and Resend need a custom domain, which
  Render serves with its own certificate.
